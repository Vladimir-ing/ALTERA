# ЛИЧНЫЙ ДОКТОР — карта агентов

Направление ALTERA, в котором работает не один чат-бот, а связка агентов.
Главный — **терапевт**: он разбирает жалобу, задаёт уточняющие вопросы, ловит
опасные признаки и определяет профиль. Дальше он передаёт разговор
**субагенту-специалисту** — тому, кто разбирается в конкретной области.

```
                     ┌──────────────────────┐
   жалоба, фото ───▶  │  ТЕРАПЕВТ            │
                     │  приём и маршрут     │
                     └──────────┬───────────┘
                                │
              красные флаги ◀───┤ 103 / 112, разговор останавливается
                                │
                                ▼  передача (handoff)
        ┌───────────────┬───────────────┬───────────────┐
        │ ДЕРМАТОЛОГ    │ ЛОР           │ НЕВРОЛОГ  ... │
        │ кожа, ногти,  │ нос, горло,   │ голова,       │
        │ волосы        │ уши           │ головокружение│
        └───────────────┘───────────────┘───────────────┘
```

Сейчас написаны двое: [терапевт](therapist.md) и [дерматолог](dermatologist.md).
Остальные профили терапевт уже распознаёт и готовит для них передачу — не хватает
только самих субагентов.

## Что здесь лежит

| Файл | Что это |

| [`dermatologist.md`](dermatologist.md) | системный промпт дерматолога: разбор кожной жалобы и фотографии |

| [`../demo/doctor.js`](../demo/doctor.js) | список профилей, красные флаги и вопросы дерматолога в машинном виде |

Список направлений и набор красных флагов живут в `demo/doctor.js` — там они
нужны демонстрации, и оттуда же их удобно брать в рабочую сборку. Промпты на них
ссылаются, но не дублируют построчно: добавили профиль в `doctor.js` — упомяните
его в таблице маршрутизации терапевта.

## Как работает передача

Терапевт не пересказывает диалог специалисту словами. Он собирает объект по
[схеме](handoff.schema.json) и отдаёт его субагенту как входные данные:

```json
{
  "from": "therapist",
  "to": "dermatologist",
  "reason": "Локальное покраснение на коже без общих симптомов",
  "complaint": "Третий день красное пятно на предплечье, чешется",
  "duration": "2-7 дней",
  "temperature": "нет",
  "attachments": [{ "kind": "photo", "note": "предплечье, дневной свет" }],
  "answers": { "site": "рука или нога", "itch": "сильно чешется" },
  "redFlagsChecked": true,
  "patientContext": { "age": 34, "chronic": [], "medications": [] }
}
```

Почему так: специалист получает одинаковый набор полей независимо от того, как
шёл разговор, и не переспрашивает то, что уже спросил терапевт. Пациент не
рассказывает одно и то же дважды — это главное, что раздражает в живой
маршрутизации между врачами.

## Правила, которые не обсуждаются

Они одинаковы для всех агентов направления и записаны в каждый промпт:

1. **Агент не ставит диагноз.** Он формулирует версии — «похоже на», «бывает
   при» — и объясняет, к какому врачу с этим идти.
2. **Агент не назначает лечение.** Рецептурные препараты, антибиотики,
   гормональные мази он не рекомендует и не отменяет.
3. **Красные флаги обрывают разговор.** Признаки состояния, при котором счёт идёт
   на минуты, — сразу 103 или 112, без уточняющих вопросов и без версий.
4. **Сомнение трактуется в сторону осмотра.** Если картина неясная, ответ —
   «нужно показать врачу», а не догадка поуверенней.
5. **Агент говорит, чего он не знает.** Не видит анализов, не слышит дыхание, не
   щупает живот — и не делает вид, что видит.

## Как добавить специалиста

1. Завести `agents/<профиль>.md` по образцу дерматолога: рамка роли, что агент
   получает на входе, свои уточняющие вопросы, формат ответа, красные флаги профиля.
2. В `demo/doctor.js` в `DIRECTIONS` поставить профилю `ready: true` и описать,
   что специалисту нужно на входе.
3. В таблицу маршрутизации в `therapist.md` добавить строку: по каким словам и
   признакам жалоба уходит в этот профиль.

Порядок важен: пока субагента нет, терапевт всё равно должен доводить человека до
живого врача — с готовой сводкой, а не с «извините, этого я не умею».
